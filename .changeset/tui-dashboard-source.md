TUI dashboard-source pattern. A dashboard is a pure `DashboardReducer<S, E>` fed by a pluggable feed through a `DashboardSource`, rendered with `useDashboard(source)` (all on `@marinoscar/platform-cli/tui`). Three feeds: `daemonAttachFeed` (read-only attach to the worker daemon's socket, reconnecting until `stop()`), `inProcessFeed` (an engine running in the process) and `pollFeed` (an HTTP poll that aborts its request on stop), plus `selectDashboardFeed` to choose between attach and embedded. The daemon socket gains an optional `channel` field on snapshot, event and log-tail frames (absent means `node`, so old daemons and old TUIs interoperate) and `registerDaemonChannel` on `@marinoscar/platform-cli/node` publishes a second engine on the same socket. `NodeDashboardSource` keeps its exports as a thin wrapper over `nodeDashboardReducer`; `startNode` accepts an `onEvent` observer. The built-in worker-node screen offers an embedded mode behind the `e` key when no worker is running, with a warning about the default heap and the memory valve. A new built-in `jobs` screen (order 35) polls `GET /api/admin/jobs/stats` and `/insights`; a 403 shows a notice, never a crash.
