Identity: the OAuth authorization server core (PP-15.4, epic #1178; docs/specs/oauth-server.md). With `IdentityModule.forRoot({ oauthServer: {} })` mounted and the `oauthServer.enabled` setting on, the API serves `GET /api/oauth/.well-known/authorization-server` (RFC 8414; `registration_endpoint` and `client_id_metadata_document_supported` stay out until PP-15.5 declares a route through `OAuthServerFeatures`), `GET /api/oauth/authorize` (validated in the spec's order: a disabled server, an unknown client or a bad redirect URI is a 302 to the web error page `/oauth/error?code=...`, never to `redirect_uri`; later errors redirect with `error`, `state` and `iss`; loopback ports are ignored for `127.0.0.1`, `[::1]` and `localhost`; PKCE `S256` only), the consent API `GET /api/oauth/requests/:id` and `POST /api/oauth/requests/:id/decision` (session credential only; a request binds to the first user who reads it; one transaction upserts the grant, inserts the code and marks the request), `POST /api/oauth/token` (`authorization_code` with PKCE and `refresh_token` with rotation; `client_secret_post` and `client_secret_basic`; a rotated refresh token presented again inside a 10-second grace window revokes its unused successor and issues a new pair, otherwise, or when the successor was used, it revokes the grant), `POST /api/oauth/revoke` (RFC 7009), and `GET`/`DELETE /api/oauth/grants` (Connected apps). Authorization codes live 60 s, pending requests 10 minutes; token lifetimes come from the `oauthServer` settings. The token endpoint makes at most five data statements and no outbound call. Audit rows `oauth:grant.create|update|revoke`, `oauth:consent.deny`, `oauth:token.reuse_detected` and the events `identity.oauth.grant.created` and `.revoked` (`IDENTITY_EVENTS`, `IdentityOAuthGrantEvent`) are written after the transaction commits. New seams: `ClientResolver` and `OAUTH_CLIENT_RESOLVER` (default `StoredClientResolver`: the rows of `oauth_clients`; PP-15.5 plugs the metadata document fetch and the trust policy in), `OAUTH_RATE_LIMITER` (an in-memory fixed window by default: 30 per minute per address on `/authorize`, 60 per minute per client on `/token` and `/revoke`; a `429` is `{"error":"temporarily_unavailable"}` with `Retry-After`; there is no global throttler guard), `OAuthServerFeatures`, `OAuthServerContext`, `OAuthGrantService`, and the test helpers `createOAuthTestClient` and `createOAuthTestPkce` in `@marinoscar/platform-api/identity/testing`.

Host: new `@RawResponse()` (`@marinoscar/platform-api/core`) opts a handler out of the `{ data, meta }` envelope, because an external standard dictates its body (the OAuth token and metadata endpoints, RFC 6749 and RFC 8414). `TransformInterceptor` skips it and the generated OpenAPI document stops describing the envelope for it (`x-raw-response`). The protocol endpoints answer RFC 6749 JSON errors through a dedicated `OAuthProtocolExceptionFilter`, applied to their controller only. `/api/oauth/token` and `/api/oauth/revoke` take `application/x-www-form-urlencoded` only (a JSON or other body is `400 invalid_request`) and at most 16 KiB: Nest's Fastify adapter already parses form bodies, so this is an `onRequest` hook scoped to those two routes, not a new parser, and no other route changes.

User data: the per-user purge (`user.data.purge`, the factory reset's per-user step and offboarding with `purge`) also deletes the user's pending `oauth_authorization_requests` (a plain `user_id` with no foreign key, so it is purged by name), and organization offboarding first revokes the organization's OAuth grants and their tokens (`revoked_reason: offboarding`, counted as `oauthGrantsRevoked`) before its slower steps.

Contract: the consent, decision, grants and token wire shapes and the OAuth error codes (`@marinoscar/platform-contract/identity`).
