Sharing: `groups.autoAcceptInvitesOnSignup` is real (#1078). The new `InviteAutoAcceptListener` (registered only when an option is on) claims a person's open, unexpired group invites from identity's `identity.user.created` event, and with the new `groups.autoAcceptInvitesOnSignIn` from every `identity.login.succeeded`. `GroupInvitesService.claimPendingForEmail(userId, email, { orgId? })` and `claimPendingForUser(userId)` do the work: the user must exist, be active and own the address; each invite is claimed in its own organization and transaction (a failing one never blocks the others or the sign-in); a new member gets the invite's role and an existing member is merged by the new `groups.inviteRoleMerge` (`upgrade-only` default, `replace`, `keep`). New event `sharing.group.invite_auto_accepted` (`GroupInviteAutoAcceptedPayload`), audit action `group:invite_auto_accepted`, metric op `invite_auto_accept`, span `sharing.invites.auto_accept`. New `SystemAccessReason` `invite-claim` (the cross-organization lookup of the open invites addressed to one user's own address; also a `SharingSystemReason`): an app whose `SharingDataPort.runAsSystem` passes reasons through needs no change. The startup "no effect" warning is gone.
