App metadata on users and organizations, more extensible models, offline checks for app indexes and policies, and a seed hook (PP-14.27). DB: migration `0036_add_app_metadata` adds `metadata JSONB NOT NULL DEFAULT '{}'` to `users` and `organizations` (each with a CHECK that the document is an object of at most 32 KiB of `jsonb` text, a backstop to the writer's 16 KiB) and a unique `(id, org_id)` key on `ai_runs` and `grants`, the target of a composite foreign key from an org-owned app table (the migration runs in the `app.rls_bypass` transaction form because both are row-level-security tables); apply it with `npm run db:sync`, then `prisma:migrate`. `Role`, `Notification`, `NotificationDelivery`, `Credential` (non-secret relations only), `AiRun` and `Grant` become `// @extensible` (a back-relation changes no SQL); `Permission` stays closed, with the reason documented. `runDbConformance({ appRoot })` gains `app-schema-objects` (every `rawSqlIndexes` and `rlsPolicies` entry of `platform.lock` is created by an app migration and dropped by none, an index definition agrees with the SQL, an unlisted partial or expression index or policy fails; the package's own entries are read, not judged) and `app-migrations`; a `rlsPolicies` lock entry gains optional `usingSha256` and `checkSha256` (`normaliseSqlExpression`, `sqlExpressionSha256`, `platform db policies` prints them), so a weakened policy is caught without a database; `platform db sync` and `platform db check` refuse an app migration named like a package migration (`APP_MIGRATION_ID_COLLISION`) or added after the last sync with a timestamp before an installed platform migration (`APP_MIGRATION_OUT_OF_ORDER`; the lock records the app directories seen at the last sync in `appMigrations`). New exports: `checkAppSchemaObjects`, `assertAppSchemaObjects`, `readAppMigrations`, `scanAllIndexes`, `checkAppMigrations`, `LockRlsPolicy`. Seed: `seedPlatform(prisma, input, { log?, extras? })` runs `SeedStep { id, run(tx, ctx) }` steps after the platform's own, each in a transaction when the client has one, under the same log, validated before any write; `assertSeedIdempotent` proves a second run creates 0; a bare `SeedLogger` third argument still works and the five fixed seed tables are unchanged. API: `registerUserMetadataSchema` and `registerOrganizationMetadataSchema` (a closed zod object per namespace; secret-named fields and open shapes are refused at registration, secret-named keys and a document over 16 KiB at write) and the injectable `IdentityMetadataService` (`get`, `set`, `update` under a row lock, `delete`; users and organizations); no platform route returns the document. Back-compat: no existing table, column, route or response changes; the OpenAPI document is unchanged. A lock written before `appMigrations` skips the ordering rule until its next sync; an app with an unlisted partial index or policy now fails `app-schema-objects` until it lists them in `platform.lock`.
