OAuth server gap closure (epic #1178). API: `GET /api/admin/oauth/refused-hosts` (`oauth_clients:read`) returns `[{ host, count, lastSeenAt }]` aggregated from the `oauth:client.refused` audit rows of the last 30 days, newest first, at most 100 hosts; `GET /api/admin/oauth/policy` (`oauth_clients:read`) returns `{ suggestedHosts }`, the app's `IdentityModule.forRoot({ oauthServer: { defaultAllowedClientHosts } })`. Both are served by the new `OAuthAdminHintsController`. The consent read (`GET /api/oauth/requests/:id`) adds `client.isNewToDeployment`: `true` when the client was first seen under 24 hours ago or no OTHER user holds an active grant with it (one indexed lookup, only for a client older than a day). Contract: `OAuthRefusedHost`, `OAuthPolicy` (and their schemas), `OAuthConsentRequest.client.isNewToDeployment` (required), `OAUTH_APPLICATION_TYPES`. Web: `createOAuthServerApi` gains `getPolicy()`, `/identity/headless` gains `useOAuthPolicy`, and `OAuthClientsPage` uses the API's suggested hosts when its `suggestedHosts` prop is absent (the prop still wins; a `404` from either route keeps the page working); the consent page shows its first-time notice from `isNewToDeployment` (the client-side 24-hour guess and `isNewClient` are gone). Infra: `csp.conf` and `csp.dev.conf` add `$frame_deny`, `$x_frame_options` and `$csp_header`; `platform/security-headers.conf` now sends `X-Frame-Options $x_frame_options` and `Content-Security-Policy $csp_header`, so `/oauth/consent` and `/oauth/error` answer `X-Frame-Options: DENY` and `frame-ancestors 'none'` with the rest of the policy (the app's `app.d/csp/` additions included) unchanged, and every other path is byte-for-byte as before. Run `platform-infra sync` after upgrading. TSDoc: exported OAuth symbols are documented and tagged so TypeDoc is warning-free.
