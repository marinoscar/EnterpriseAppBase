Extension-author test kits for Doctor checks and job handlers, and configurable web conformance suites (PP-14.26, #944).

API. New subpath `@marinoscar/platform-api/doctor/testing`: `describeDoctorCheckConformance(name, factory, { scenarios })` proves one check against the contract (identity, a guarded run that never throws, a valid outcome with a remedy on `warn` and `fail`, no seeded secret, read-only); `runDoctorCheck`, `findOutcomeProblems` and `findIdentityProblems`; and the doubles it runs over, `createRecordingPrisma` (records every call, refuses `create`, `update`, `upsert`, `delete`, `*Many`, `$executeRaw` and a raw write statement) and `createWriteFailingStorage`. Importing the entry registers the `doctor-read-only` conformance suite (`runPlatformConformance({ suites: { doctorReadOnly: { fixture, minChecks?, exempt?, forbiddenServices? } } })`), which runs the same proof over every check of the booted app's `DoctorCheckRegistry`: none writes through Prisma or to storage, none holds a side-effecting "test" service, and each check whose `dependsOn` passed returns a valid outcome. An app that does not list the key runs nothing.

`@marinoscar/platform-api/jobs/testing` gains `createFakeJobQueue()` (an in-memory queue with the real dedup rule, claim order, attempt budget and delete decision; `asJobsService()` for a service under test), `describeJobHandlerConformance(name, handler, { payloads })` (type, label, a profile of exactly two numbers inside ceilings, the node pair both or neither, `ai.*` server-only; per payload a settle, a double run, a failure by throwing, dedup and `canDelete`) and the pure `findJobHandlerContractViolations(handler)`. `@marinoscar/platform-api/testing` gains `resolveConformanceTestApi`, the helper both kits use. The `doctor` slice now lists `testing` as a slice dependency (`packages/platform-slices.json`); the testing README documents adding a suite from an app with `conformanceSuites.register` and a `declare module` augmentation.

Web. `runPlatformWebConformance({ suites })` takes `Record<string, options | { skip: 'reason' }>`: the entry under a suite's id is handed to `register(api, context, options)` as a third argument (`WebConformanceSuite<TOptions>`, default `undefined`, so the `settings-*` suites are unchanged). `webConformanceSuites.register` now throws on a duplicate id instead of ignoring it (a testing entry imported once registers once; guard a repeat with the new `webConformanceSuites.has(id)`). The `expect` subset gains `toBe`, `toMatchObject`, `toHaveLength` and `toThrow`; a hand-written `WebConformanceTestApi` fake must provide them.
