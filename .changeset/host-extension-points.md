Host: the health probes, the maintenance window, the About report, the deployment modes, the global guards and the response envelope are open to the app. `registerHealthIndicator({ id, critical, check, timeoutMs? })` adds an indicator to `GET /api/health` and, when critical, to `/api/health/ready` (the `database` indicator registers through the same function; details are bounded and secret-filtered because the probes are public; `/live` is unchanged). `registerMaintenanceBypass({ id, allows })` lets a request through an open window after the built-in admin rule; it is fail-closed (only `true` allows) and passes the window, not authentication. `registerAboutContributor({ id, label, describe })` adds `extras` to `GET /api/admin/about` and sections to the web `AboutPage` (the DOM is unchanged when none is registered). `registerDeploymentMode` and `registerDeploymentCapability` open `DEPLOYMENT_MODE` and `DeploymentModeService.can`; `DEPLOYMENT_MODES` is a deprecated alias of `BUILTIN_DEPLOYMENT_MODES` and `DeploymentMode` widens to any registered id (so do `DbBackupDeploymentMode` and `UserDataEnvironment`). The `host` conformance suite takes `allowedAppGuards: [{ name, why }]` (an empty `why` throws) and now requires `MaintenanceGuard` to be the first `APP_GUARD`. `PlatformHostCoreModule.forRoot({ host, permissions })` and `AboutModule.forRoot({ host, permission })` route the host controllers through the app's access decorators and permission strings (defaults unchanged). `buildCorsOptions(raw, extra?)` adds `methods`, `allowedHeaders`, `exposedHeaders` and `maxAge`; `registerResponseMetaContributor` adds bounded keys to the envelope `meta`. OpenAPI: `GET /api/admin/about` gains an optional `extras` array and `api.deploymentMode` is an id pattern instead of a two-value enum. Migration: `capabilitiesFor` throws for a mode nobody registered; `HealthController`'s constructor takes a `HealthIndicatorRunner` in place of `DatabaseHealthIndicator`.
